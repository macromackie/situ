# Situ visual language

Use Berkeley Mono throughout, with compact line heights and normal glyph proportions. The shell uses quiet blue/slate negative space, a stable left project tree, and an inset white page. Keep navigation in place when a project is selected. Reading content is centered; a source rail meets the right edge of the page. On small screens the source rail follows the content.

The technical-sheet reference supplies thin rules, square figure frames, connected captions, aligned numbers and restrained color. It does not require a mosaic dashboard, letter labels on every box, decorative rulers or condensed type.

A page has one main reading direction. Put substantive figures in ruled frames; attach metadata and exact values to their figure. Use a brief left rule for an interpretation and a quiet outlined area for the next test. Related questions use whole-row links with one destination. Controls get `user-select: none`; prose and observations remain selectable.

Now answers what we understand and what happens next. Question pages hold the deeper measurements and examples. Timeline shows source-backed chronology. Updates explain changes to understanding. Raw work, jobs, leases and discussion are in Inspect.

Dense charts retain exact observations as an accessible table. Scenario comparisons label metric, units, cohort and evaluator. Tooltips and icon labels supplement visible meaning; color is never the only signal. Missing data and unavailable media stay explicit. Ordinary loading or refresh failures preserve readable content when a prior account is available.

Storybook is the component reference. `stories/fixtures.ts` and all media under `stories/assets` are synthetic and contain no private reference screenshots. The media generator creates a simple navigation scene; it does not depict a trained model.
